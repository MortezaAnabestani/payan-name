# گزارش پلی‌تست انسانی U1 — برش Next.js

وضعیت: ثبت یافته برای بازطراحی. این برش از «اعتبارنیافته/پلی‌تست‌نشده» به «پلی‌تست‌شده / رضایت کم / بازطراحی لازم» تغییر وضعیت یافت.

## ۱. شناسنامه

| فیلد | مقدار |
|---|---|
| اثر مبنا | «سه قطره خون» — واحد U1 |
| نسخه | `game/` (`three-drops-u1-v1` / SCHEMA 1) |
| تاریخ | ۲۰۲۶-۱۰-۲۳ |
| مسیر اجرا | `http://localhost:3000` |
| شرکت‌کننده | P1: کاربر پروژه (پلی‌تست کامل انسانی)؛ عامل: پیمایش خودکار مستقل (همان مسیر منطقی، بدون شنیدن صدا) |
| نتیجه P1 | رضایت ≈ **۳۰٪** |
| شاهدهای فنی | بدون خطای کنسول؛ ذخیره/بازه سالم؛ مسیر کامل بدون مکث‌کردن باگ |

مسیر عامل: دعوت → پیش‌درآمد → میز (۳ پیش‌نویس بی‌موتیف) → قفل → «عبارت را نگه می‌دارم» → تفسیر (ادعای «خود» + شاهد ۱) → «پرونده را پاره می‌کنم» → پایان «سه قطره روی انگشت».

## ۲. نقد P1 در چهار محور + شاهدهای مستقل عامل

### محور ۱ — شبیه سایت است تا بازی
- ورودی تایپ + دکمهٔ «ثبت در پرونده»؛ تفسیر = `fieldset ادعا` + چک‌باکس شاهدها + دکمهٔ ثبت: همان هشدار ref 08 («اگر همه‌چیز در منو/فرم است، اثر سامانهٔ اداری می‌شود»).
- کنار صفحه: HUD آماری با dl «فشار پنهان / هم‌دستی / مقاومت / موتیف» — نمایش وضعیت داخلی به سبک پنل ادمین.
- هیچ مانع/چالش/هزینه‌ای جلوی نوشتن نمی‌ایستد؛ «قفل» فقط حاصل شمردن است، نه چیزدی که حس شود.
- رگه‌های وب‌سایتی: eyebrow «برش عمودی — واحد ۱»، footer «برش عمودی U1 — اعتبارنیافته / پلی‌تست‌نشده» هم‌زمان با بازی روی صفحه است.

### محور ۲ — تشریح نظری/آموزشی، نه قصه
- در پیش‌درآمد مستقیماً برای بازیکن: «واحد U1، سطح ۲، مسلط: روایت‌زاد + عاملیت مؤلف. کارکرد: تعلیق عاملیت بیان و اعتماد به کانال روایت. شکاف باید انجام شود، نه فقط خوانده شود.» — واژگان رساله در UI.
- در میز: «“بازوی بی‌حس” در وب معادل بدنی مستقیم ندارد؛ لرزش نشانگر، کندی ورود و قطع صدا جای آن را می‌گیرند.» — یادداشت طراح/توسعه، روی صفحه.
- در تفسیر: «“سه قطره خون” تنها دالی است که رابط خوانا نگه می‌دارد» — واژگان نشانه‌شناسی.
- متن منبع با «بازهٔ کاراکتری ۵۶۵–۱۲» برای بازیکن.

### محور ۳ — داده، نه کپسول تفسیرپذیر
- پایان/پروندهٔ تفسیر = آمار و لیست (تلاش‌ها، موتیف، ادعا، شاهدها)؛ دفتر = جدول.
- موتیف فقط رشتهٔ متنی است (string-match)؛ «شیء» تفسیرپذیری که بتوان لمس/چرخاند/واکنش ببینید وجود ندارد؛ «کاوش برای تفسیر» کم و عمدتاً مصراع‌واره است.

### محور ۴ — هنر تک‌رسانه‌ای (کلام)
- اندازه‌گیری عامل در پایان: ۰ canvas، ۰ video، ۱ SVG استاتیک، ۰ انیمیشن فعال؛ فونت واحد.
- صدا: ۴ افکت کوتاه (خش/لرز/chime/thud) + هم؛ بدون soundscape، بدون تم موتیف، بدون تغییر فضایی.
- هنر در ماتریس هویت عملاً N/A بود؛ درحالی‌که کانسپت A، نور/صدا/فضا را پیش‌آمد تجربه می‌داند.

## ۳. یافته‌های تکمیلی عامل

- **بهترین لحظه:** `DecayText` (زوال حرف‌به‌حرف آخرین ثبت) — زبان رایانشیِ اصیل؛ اما بیرون از کاغذ اصلی، به‌صورت پنل زیر فرم.
- قفل با تایپ مستقیم موتیف فوری رخ می‌دهد؛ مسیر «تلاش بی‌ثمر» و «کشف موتیف» جدا نبودند (عامل مسیر بدون موتیف را آزمود).
- پیش‌درآمد خوب پنجمید؛ اما قاب «پروندهٔ اداری» + یادداشت نظری لحن را خراب می‌کنند.
- صدا همیشه‌روشن پیش‌فرض است؛ ولی سکوتِ میانmakers جز حشْ دو نیست — «فضای صوتی» وجود ندارد.

## ۴. ترجمه به ماتریس هویت هفت‌حوزه‌ای (برش U1)

| حوزه | وضعیت | توضیح |
|---|---|---|
| طراحی بازی | **fail** | فعل/مانع/پیشرفت/شکست در ظاهر دست نیست؛ حلقه به «تکمیل فرم» فرومی‌کاهد |
| فنی | pass | معماری لایه‌ای، رخداد-محوری، دسترسی، کیفیت ورودی/خروجی |
| قصه | weak | خطوط قصه خوب ولی لحن نظری/فرم اداری آن را می‌پوشاند |
| هنر | **fail** | فقط تایپوگرافی؛ بدون هنر صحنه/کاغذ/نور |
| صدا | **fail** | SFX حداقلی؛ بدون پس‌زمینه/موتیف صوتی |
| UI/UX | partial | دسترسی و آموزش خوب؛ بازخورد صحنه‌ای کم |
| هویت تراگشتی | partial | مکانیک زوال واقعی و ارزنده؛ اما نمایش/آستانهٔ چندرسانه‌ای کم |

## ۵. تصمیم ثبت‌شده

- برش U1 «کد-سالم / تجربه-ناقص»؛ بازطراحی تجربه در سه محور: صحنهٔ دیجتیک میز (کاغذ/قلم/قطره‌های موتیف به‌عنوان شیء) + حذف کامل واژگان نظری از UI + لایهٔ هنر/صدا (بستری که گهگاه فقط سکوت نباشد).
- بازطراحی روی همان اسکلت (`game/`، بدون تغییر معماری domain)؛ ماتریس هویت U1 پیش از کد، سندیت یابد؛ سپس پلی‌تست دوم.
