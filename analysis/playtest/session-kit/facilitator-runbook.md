# Runbook تسهیل‌گر — روزِ نشست (U1 v2 / U2 / U3)

یک صفحه، ترتیب اجرا. جزئیات سنجش در پروتکل هر واحد است؛ این فایل فقط «چه کاری،
کِی، با چه حدِ مجازی» را می‌گوید. پرانتزها ارجاع‌اند، نه جایگزین خواندن پروتکل.

## §۰ — یک هفته پیش از نشست

- [ ] ۵–۷ دعوت‌نامه ارسال (برای ۵ نفر کامل؛ buffer دو نفر برای لغو). ترکیب (§۲ مرجع skill): ≥۳ ناآشنا با منبع، ≥۱ کم‌تجربهٔ ژانر، ≥۱ آشنا با منبع؛ تنوع جنسیت/سن/دسترسی.
- [ ] برای U1: شرکت‌کنندهٔ P1 (دور اول) اولویت دعوت — مقایسهٔ مستقیم v1/v2 (پروتکل `phase-1/03` §۲).
- [ ] intake form (`participant-intake-form.md`) برگشتی‌ها بررسی شد → نیازهای دسترسی (عینک/هدفون/صفحه‌خوان/موبایل) ثبت شد.
- [ ] اتاق/ابزار: مرورگر دسکتاپ + گوشی Android/iPhone یا DevTools عرض ۳۹۰ + هدفون + (برای سناریوی TTS) VoiceOver/NVDA.
- [ ] تسهیل‌گر و ثبت‌کننده دو نفر متفاوتند؛ هر دو §۴ همین فایل را خوانده‌اند.

## §۱ — شب پیش از نشست

- [ ] `npm run test && npm run build` موفق (مرجع: `analysis/phase-0/04-phase-0-gate.md` — آخرین وضعیت سبز).
- [ ] dry run کامل خودت: از دعوت تا پایان + آرشیو پس‌ازپایان؛ کنسول بی‌خطا.
- [ ] چاپ/آماده‌سازی: `consent-form.md` (یک برگه per بازیکن)، `observation-log-template.md` (یک برگه per بازیکن)، قلم.
- [ ] تایمر گوشی، ساعت دیواری/تایمر نمایشگر.

## §۲ — ۱۰ دقیقه پیش از نشست (چک‌لیست فنی)

مرجع تفصیلی: پروتکل U1 §۳ (برای U2/U3 همان مراحل با مسیر آن واحد).

- [ ] `npm run dev` → `http://localhost:3000` بالا آمد.
- [ ] **localStorage پاک** — Console: `localStorage.clear()` سپس رفرش. (کلید فعال: `three-drops:session:v1`؛ کلید قدیمی `three-drops:u1:v1` عمداً خوانده نمی‌شود. اگر نشست قبلی ناقص ماند، «شروع از نو» از پشت جلد هم کافی است.)
- [ ] تنظیمات پیش‌فرض: صدا روشن، کاهش حرکت خاموش، کنتراست عادی، اندازهٔ متن معمولی.
- [ ] صدای سیستم در سطح شنیدنی؛ هدفون وصل.
- [ ] پنجره ≈۱۲۰۰؛ متن منبع/گزارش تحلیل روی صفحه باز نیست.
- [ ] کنسول F12 باز و بی‌خطا؛ شبکه بدون ۵۰۲.

## §۳ — ورود بازیکن (۳ دقیقه)

- [ ] رضایت‌نامه امضا شد (ضبط صدا/تصویر تیک جدا دارد؛ بدون تیک = فقط یادداشت دستی).
- [ ] کد نشست امروز داده می‌شود — از پیش‌شماره‌گذاری پروتکل خودِ واحد: U1 دور دوم → `P2-__` (پروتکل `phase-1/03` §۲)، U2 → `Q-__` (پروتکل `phase-1/08` §۲)، U3 → `R-__` (پروتکل `phase-1/11` §۲). بازیکنی که در چند واحد شرکت می‌کند کد ثابتش را نگه می‌دارد. (پیش‌ثبت در ستون id scorecard.)
- [ ] جملهٔ قاب (بدون تغییر): «این یک برش کوتاه از یک اثر ادبی تعاملی است؛ داریم تجربه را آزمایش می‌کنیم، نه تو را. هر کاری بکنی درست است.»
- [ ] توضیح حق توقف: «هر لحظه خواستی بگو متوقف می‌کنیم.»

## §۴ — حین بازی (۱۰–۱۵ دقیقه) — قانون تسهیل‌گر

- ساکت. فقط مشاهده و زمان‌سنجه (log template).
- **ممنوع:** گفتن «برگه را نگاه کن»، «دکمه K را بزن»، توضیح موتیف/ناظم/زوال، «درست/غلط»، «خوشت آمد؟».
- **مجاز:** اگر >۲ دقیقه هیچ تعاملی نبود → فقط «الان چه می‌بینی؟»؛ اگر لازم شد اشارهٔ غیرمستقیم به شیء روی میز. گیر فنی (صفحه سفید/خطای شبکه) → رفع فنی و ثبت در log.
- زمان‌سنجه‌های اجباری: نخستین تایپ، رسیدن به قفل، مکث‌های >۵ ثانیه، واکنش کلامی به زوال/قطره‌ها/صداهای ایستگاه.
- انتهای فازها را ثبت کن (نه تفسیر): U1: کدام قفل (K/Esc) + کدام ادعا/کنش؛ U2: ضربه تا ظهور اول/سوم + دفترچه(K) یا انکار؛ U3: ترتیب ایستگاه‌ها + رسیدن به روز دوم + ادعای محوشونده.

## §۵ — مصاحبه (۵–۷ دقیقه)

- پرسش‌های باز پروتکل همان واحد را به ترتیب بپرس؛ گزینه‌ها را نخوان؛ جواب‌ها را کلمه‌به‌کلمه بنویس (نقل‌قول = داده).
- سپس پرسش‌های بسته (رضایت ۰–۱۰۰، آسانی ۱–۵، حس حضور ۱–۵، وضوح قفل/پیامد ۱–۵، احتمال ادامه ۱–۵) → اعداد مستقیم به scorecard.
- U1+: اگر P1 حاضر است، پرسش مقایسهٔ v1/v2 (پروتکل §۶).

## §۶ — آزمون‌های تکمیلی (همان نشست یا نشست دوم)

| آزمون | روش | ثبت |
|---|---|---|
| بی‌صدا | خاموش از پشت جلد؛ فقط برای کسی که نشست اصلی را دیده | «چه چیزی جا افتاد؟» کلمه‌به‌کلمه |
| کاهش حرکت | روشن از پشت جلد | زوال خوانا ماند؟ تجربه نابود شد؟ |
| کیبورد | بدون ماوس تا پایان یکی از مسیرها: Tab/Enter/K/Esc | گیر/سرریز تمرکز |
| عرض ۳۹۰ | گوشی واقعی یا DevTools | پوشیدگی/سرریز؛ نوار بایگانی داخل جریان صفحه — گیج‌کننده بود → باگ |
| صفحه‌خوان | VoiceOver/NVDA؛ ادعای محوشونده U3 بصری محو می‌شود ولی srOnly همیشه خوانا است | داوری: آیا «خوانده‌شدن≠ثبت‌شدن» بدون چشم منتقل می‌شود؟ |

## §۷ — بلافاصله پس از نشست (حافظه تازه، ≤۳۰ دقیقه)

- [ ] log مشاهده کامل شد؛ نقل‌قول‌ها تمیز شدند (بدون بازنویسی معنا).
- [ ] ردیف بازیکن در `session-scorecard.csv` پر شد؛ ستون `complete`: بله=`yes`/نصفه=`no`.
- [ ] پیش‌نویس گزارش: `templates/uX-report.md` → `reports/YYYY-MM-DD-uX-Pn.md`.
- [ ] فایل‌های ضبط (فقط با رضایت) خارج از repo؛ در گزارش فقط کد اشاره شود.

## §۸ — جمع‌بندی پذیرش (پس از ≥۵ ردیف کامل)

نسبت‌ها را از scorecard حساب کن و در گزارش بنویس؛ معیارها از پروتکل همان واحد:

- **U1 (`phase-1/03` §۸):** هیچ «فرم/ثبت/تکمیل» در توصیف؛ ≥۴/۵ تفاوت ثبت‌شدن/خوانده‌شدن؛ ≥۴/۵ بازگویی قصه؛ ≥۴/۵ مکث/لمس؛ پیامد یادآوری‌شده؛ بی‌صدا «چیزی جا افتاد»؛ صفر متای وب؛ کیبورد کامل؛ صفر خطای کنسول/باگ بحرانی. شکست در ≥۲ بند ← «نیازمند دور سوم»؛ فقط بندهای کیفی مرزی ← اصلاح کوچک + پلی‌تست هدفمند.
- **U2 (`phase-1/08`):** نسبت‌ها را از بند‌های چک‌لیست پذیرش همان پروتکل حساب کن؛ در این فایل عدد مستقلی تکرار نمی‌شود تا دو منبع یکی نشوند (مرجع = پروتکل U2 §معیارهای پذیرش).
- **U3 (`phase-1/11`):** ≥۴/۵ درهای بازگشتی، ≥۴/۵ روز دوم در همان روز، ≥۳/۵ «خودم فهمیدم».
- حکم → گزارش §تصمیم + به‌روزرسانی `analysis/phase-0/04-phase-0-gate.md` (سطر واحد مربوطه و «گام بعدی»).

## §۹ — اخلاق/حریم (همیشه جاری)

- توقف بی‌درنگ با درخواست بازیکن یا نشانهٔ ناراحتی؛ دلیل در گزارش.
- محتوای حساس منبع (زهر/مرگ): پیش‌آگاهی در consent form؛ بدون لو‌دادن پایان قبل از بازی.
- عدم فریب دربارهٔ ماهیت نشست؛ جبران وقت توافق‌شده.
