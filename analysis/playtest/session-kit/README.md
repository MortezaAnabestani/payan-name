# کیت نشست انسانی — پلی‌تست U1 (v2) / U2 / U3

این پوشه «زیرساخت نشست» است: هر چیزی که تسهیل‌گر و ثبت‌کننده پیش و حین و پس از یک
نشست واقعی به آن نیاز دارند، بدون این‌که لازم باشد پروتکل‌ها را دوباره بخواند یا
از خودشان عدد بسازند. **هیچ داده‌ای اینجا جعل نمی‌شود**؛ همهٔ فرم‌ها تا اجرای
واقعی خالی می‌مانند.

## اعضا و نقش‌ها

| نقش | وظیفه | ممنوع |
|---|---|---|
| تسهیل‌گر | خوش‌آمد، تایمر، مشاهده، مصاحبه | توضیح طراحی، گفتن «درست/غلط»، راهنمایی مکانیکی (§۴ پروتکل U1: «هرگز نگو برگه را نگاه کن») |
| ثبت‌کننده | یادداشت زمان‌دار، نقل‌قول کلمه‌به‌کلمه، تیک چک‌لیست‌ها | تفسیر نظری حین نشست، پرکردن فرم به‌جای بازیکن |
| ناظر دسترسی (در نشست صفحه‌خوان) | اجرای سناریوی TTS با VoiceOver/NVDA | راهنمایی بازیکن نابینا دربارهٔ محتوای پنهان |

بازیکن = شرکت‌کنندهٔ بیرونی. حداقل ۵ نفر، دست‌کم ۳ نفر ناآشنا با منبع
(`skills/transpositional-literary-games/references/13-playtest-acceptance.md` §۲).
برای دور دوم U1، شرکت‌کنندهٔ P1 اولویت دعوت دارد (مقایسهٔ مستقیم v1/v2).

## ساختار پوشه

```
session-kit/
  README.md                        ← همین فایل
  facilitator-runbook.md           ← چک‌لیست گام‌به‌گام روزِ نشست (U1/U2/U3)
  participant-intake-form.md       ← پیش‌پرسش + رضایت (ورودی بازیکن)
  consent-form.md                  ← متن رضایت‌نامهٔ قابل چاپ (فارسی)
  observation-log-template.md      ← برگهٔ مشاهدهٔ زمان‌دار (کار ثبت‌کننده)
  session-scorecard.csv            ← آرایهٔ نمرات → معیارهای پذیرش (ماشین‌خوان)
  templates/                       ← قالب خالی گزارش نهایی (به reports/ کپی کنید)
  reports/                         ← گزارش‌های پرشدهٔ نشست‌های واقعی
```

## جریان کار (هر نشست)

1. **پیش از نشست (روز قبل):** دعوت با intake form (`participant-intake-form.md`)؛
   بررسی تطابق با ترکیب §۲ مرجع skill؛ تعیین تسهیل‌گر/ثبت‌کننده.
2. **۱۰ دقیقه پیش از نشست:** اجرای `facilitator-runbook.md` §۱–§۳ (محیط، بیلد،
   localStorage، dry run). امضای رضایت‌نامه (`consent-form.md`).
3. **حین نشست:** ثبت در `observation-log-template.md` (یک برگه per بازیکن).
4. **بلافاصله پس از نشست (حافظه تازه):** تکمیل ردیف بازیکن در
   `session-scorecard.csv` و نوشتن پیش‌نویس گزارش از `templates/`.
5. **پذیرش:** وقتی ≥۵ ردیف کامل شد، ستون‌های scorecard را با معیارهای پذیرش
   پروتکل مربوطه (`analysis/phase-1/03`, `analysis/phase-1/08`,
   `analysis/phase-1/11`) تطبیق دهید و حکم را در گزارش +
   `analysis/phase-0/04-phase-0-gate.md` ثبت کنید.

## قواعد صداقت (برگرفته از skill §۱۲ و اصل ۱۰)

- تا دادهٔ واقعی وارد نشده، هیچ بندی تیک نمی‌خورد؛ هیچ عددی «تقریبی» ثبت نمی‌شود.
- هر ادعای تجربه یا «اعتبارنیافته» برچسب می‌خورد یا شاهد (نقل‌قول/زمان‌سنجه) دارد.
- بازیکنان فقط با کد (`P2-01` …)؛ نام و هویت در هیچ فایل این repo نمی‌آید.
- ضبط صوت/تصویر فقط با تیک رضایت جداگانه؛ فایل‌های خام خارج از repo نگهداری شوند.
- اگر نشست نصفه ماند یا بازیکن کنار کشید، در گزارش با دلیل ثبت می‌شود و آن
  بازیکن در نسبت‌های پذیرش شمارش نمی‌شود (ستون `complete` در scorecard: `no`).
