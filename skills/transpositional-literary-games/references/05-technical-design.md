# ۰۵ — طراحی فنی

## ۰. قاعده

موتور و معماری را از **تجربه** انتخاب کن، نه از عادت. اگر تجربه به فضای سه‌بعدی، فیزیک، نورپردازی، صداى فضایی و عاملان حالت‌مند نیاز دارد، DOM ساده کافی نیست.

«بازی در مرورگر» اشکالی ندارد؛ اما «صفحهٔ HTML با چند div» با بازی اشتباه نشود.

## ۱. تصمیم موتور

| موتور | مناسب | نامناسب | ریسک |
|---|---|---|---|
| Godot | دوبعدی/سه‌بعدی، تیم کوچک، بیلد سریع | نیاز به pipeline سفارشی سنگین | کمتر |
| Unity | ابزار و asset store، سه‌بعدی/دوبعدی | تیم کوچک/بودجه محدود | متوسط |
| Unreal | سه‌بعدی با کیفیت بالا | پروژهٔ کوچک/دوبعدی | سنگین |
| WebGL/Three.js | تجربهٔ مرورگری، فضای سه‌بعدی سبک | فیزیک/نورپردازی سنگین | متوسط |
| Custom | نیازهای خاص | نداشتن تیم فنی | بالا |
| DOM/Canvas | اثر کوتاه/فرم‌محور | بازی جهان‌محور | بالا |

**معیار:**

- پلتفرم هدف.
- نیاز فضایی/دوربین.
- نیاز فیزیک/نور.
- نیاز صداى فضایی.
- نیاز AI.
- اندازهٔ تیم.
- زمان/بودجه.
- pipeline هنری.
- ذخیره/بارگذاری.
- دسترسی‌پذیری.

## ۲. معماری

```text
Input → Game State → Systems → Presentation
                ↘ Save/Load
                ↘ Telemetry (اختیاری/با رضایت)
```

### ۲.۱ لایه‌ها

- **Core:** وضعیت، قواعد، زمان، رویدادها.
- **Simulation:** فیزیک، ناوبری، عاملان، اقتصاد.
- **Narrative:** مأموریت، دیالوگ، حالت قصه.
- **Presentation:** دوربین، انیمیشن، VFX، UI، صدا.
- **Platform:** ورودی، ذخیره، تنظیمات، بیلد.

### ۲.۲ قاعدهٔ وابستگی

Core نباید به UI/موتور وابسته باشد. Narrative نباید وضعیت را مستقیم دستکاری کند؛ از رویداد/فرمان استفاده کن.

**آزمون:** آیا می‌توانی وضعیت را در هر لحظه ذخیره/بازسازی کنی؟

## ۴. داده و محتوا

- داده‌ها از کد جدا باشند (JSON/YAML/CSV/Resource).
- schema برای دیالوگ، مأموریت، کارت واحد، NPC.
- اعتبارسنجی در build.
- نسخه‌بندی داده.
- بومی‌سازی/زبان.
- متن‌های بلند در فایل‌های قابل‌ویرایش.

```text
data/
  units/
  dialogue/
  quests/
  npcs/
  items/
  localization/
```

## ۵. ذخیره/بارگذاری

- چه چیزی ذخیره می‌شود؟ (وضعیت، جهان، رابطه، دانش، اقتصاد)
- چه چیزی بازسازی می‌شود؟
- ذخیرهٔ خودکار/دستی؟
- چند اسلات؟
- سازگاری نسخه؟
- ذخیرهٔ امن/بازیابی؟
- ذخیره‌های خراب؟

**قاعده:** اگر ذخیره/بارگذاری نباشد، بازی کامل نیست.

## ۶. فضا/دوربین/حرکت

- دوبعدی/۲.۵بعدی/سه‌بعدی.
- دوربین: ثابت، دنبال‌کننده، آزاد، سینمایی.
- ناوبری: پیاده، ریلی، نقطه‌ای، شناور.
- مقیاس/فاصله/سرعت.
- مرزها/بارگذاری.
- تعامل با محیط.

**آزمون:** آیا فضا بخشی از قصه/پروتکل است یا فقط پس‌زمینه؟

## ۷. ورودی

- کیبورد/ماوس.
- گیم‌پد.
- لمسی.
- ورودی جایگزین.
- بازنقشه‌پذیری.
- حساسیت.
- بازخورد لمسی.

## ۸. کارایی

- FPS هدف.
- زمان بارگذاری.
- بودجهٔ draw call/پالیگان/تکسچر.
- حافظه.
- اندازهٔ بیلد.
- پلتفرم حداقل.
- پروفایلینگ.

| بودجه | هدف |
|---|---|
| FPS | ۶۰ (یا ۳۰ پایدار) |
| بارگذاری | < ۱۰ ثانیه برای صحنه |
| ذخیره | < ۱ ثانیه |
| ورودی→بازخورد | < ۱۰۰ms |

اعداد را با پلتفرم/اثر تنظیم کن.
